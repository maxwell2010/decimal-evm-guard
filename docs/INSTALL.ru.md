# Установка Decimal EVM Guardian

Это отдельный сервис для наблюдения за подписями валидатора. Он может отправить только подписанную EVM-транзакцию `pauseSelf()`. Сервис не включает валидатора, не останавливает ноду, не очищает базы, не меняет trust block и не устанавливает timer.

## Требования

- Linux с systemd, Python 3.10+, `venv`, `curl`, `tar`, `sha256sum`.
- Два независимых CometBFT RPC одной сети, не принадлежащих проверяемой ноде.
- Доступный EVM RPC сети Decimal и средства на EVM-кошельке валидатора для комиссии.
- Консенсусный адрес валидатора и его отдельный EVM-ключ.

## Установка

Изучите исходный код и [релиз](https://github.com/maxwell2010/decimal-evm-guard/releases) перед установкой. Команды для последнего релиза:

```bash
curl -fsSLo /tmp/install-decimal-guardian.sh https://github.com/maxwell2010/decimal-evm-guard/releases/latest/download/install-release.sh
sudo bash /tmp/install-decimal-guardian.sh
```

Для закрепленной версии передайте тег, например `sudo bash /tmp/install-decimal-guardian.sh v0.3.2`. Установщик проверяет SHA-256 архива, сохраняет существующий конфиг и не запускает сервис. Он не запрашивает и не копирует ключи из других сервисов.

## Конфиг

Файл `/etc/decimal-guardian/config.json` создается из короткого примера с `enabled: false`. Замените вымышленные адреса RPC и нулевой консенсусный адрес. Файл принадлежит root, права `0600`.

| Поле | Назначение | Исходное значение |
| --- | --- | --- |
| `node_name` | Имя узла в журнале и Telegram-уведомлении | `validator-1` |
| `enabled` | Разрешить работу guard | `false` |
| `consensus_address` | Hex-адрес из публичного поля `address` файла `priv_validator_key.json` | заменить нули |
| `references` | Два разных удаленных CometBFT RPC. Guard сравнивает их блоки и подписи; при расхождении не отключает валидатора | заменить заглушки |
| `window_blocks` | Сколько последних подтвержденных блоков проверять | `24` |
| `max_missed` | При скольких пропущенных подписях в этом окне отключить валидатора | `8` |
| `max_consecutive_missed` | При скольких пропущенных подписях подряд отключить валидатора, даже если общий порог еще не достигнут | `6` |
| `poll_seconds` | Как часто повторять проверку, в секундах | `5` |
| `block_timeout_seconds` | Сколько ждать нового блока; при более долгой остановке сети предупредить в журнале и не отправлять транзакцию | `30` |
| `max_lag` | Максимальная допустимая разница высот двух RPC в блоках; при большей разнице проверка отклоняется | `3` |
| `cooldown_seconds` | Минимальный интервал между попытками отключения, в секундах | `900` |
| `telegram.bot_token` | Токен бота для уведомления об отключении | `null` - не отправлять |
| `telegram.user_id` | Числовой ID получателя | `null` - не отправлять |

Остальное можно не указывать: используются локальный EVM RPC `http://127.0.0.1:8545`, `chain_id=75`, адрес контрактного реестра Decimal mainnet `0xc108715a06f76caa96fa2c943ebf05159c29a87d`, файл ключа `/etc/decimal-guardian/validator.key` и каталог состояния `/var/lib/decimal-guardian`. Через реестр сервис узнает адрес действующего контракта валидаторов, в который отправляет `pauseSelf()`. Проверка chain ID перед подписью остается обязательной. Для другой сети явно задайте `chain_id` и `contract_center`; без адреса реестра для другой сети конфиг не пройдет проверку.

Отключение происходит, когда достигнут `max_missed` за `window_blocks` или `max_consecutive_missed` подряд. Эти значения указаны в примере явно, чтобы оператор видел условия защитной паузы до запуска. Уведомление содержит `node_name`, достигнутый порог (или оба), фактические числа и хэш подтвержденной транзакции. Остальные параметры управляют проверкой, но сами не вызывают отключение.

Telegram необязателен. Укажите оба поля или оставьте оба `null`. Бот должен иметь возможность написать пользователю. Сообщение отправляется только после подтвержденной транзакции `pauseSelf()`; при уже отключенном валидаторе повторного уведомления нет. Ошибка доставки не влияет на защитную паузу. Никогда не публикуйте настоящий токен бота в Git.

Пороги взяты как осторожный начальный пример, а не универсальная гарантия. Проверьте их по реальной работе валидатора и сети. Если RPC расходятся, guard не отправляет транзакцию.

## Ключ

Используйте только свой EVM-ключ валидатора. Не копируйте секреты из чужих `.env` и не публикуйте свои в Git, issue, shell history или логах. Секретный файл должен быть обычным файлом с правами `0600` в каталоге `0700` и содержать один из двух форматов:

```json
{"private_key":"0xЗАМЕНИТЕ_НА_СВОЙ_КЛЮЧ"}
```

```json
{"mnemonic":"ЗАМЕНИТЕ_НА_СВОЮ_СЕКРЕТНУЮ_ФРАЗУ"}
```

Путь деривации для фразы задан в коде: `m/44'/60'/0'/0/0`. В конфиге и файле ключа его указывать не нужно. Фраза дает доступ ко всем производным кошелькам, поэтому отдельный приватный ключ предпочтительнее. Убедитесь, что получаемый EVM-адрес принадлежит именно вашему валидатору. Консенсусный адрес из `priv_validator_key.json` не является этим EVM-адресом. Поле `priv_key` из файла Decimal Guardian не читает.

## Проверка и запуск

Сначала проверьте источники в режиме только чтения:

```bash
sudo /opt/decimal-guardian/venv/bin/decimal-guardian guard-check
sudo /opt/decimal-guardian/venv/bin/decimal-guardian doctor
```

`guard-check` сравнит подписи на двух RPC. `doctor` дополнительно проверит EVM-ключ, chain ID и состояние валидатора. Обе команды не подписывают транзакции. После успешной проверки установите `enabled: true`, затем вручную запустите сервис:

```bash
sudo systemctl enable --now decimal-guardian.service
systemctl status decimal-guardian.service
journalctl -u decimal-guardian.service -n 100 --no-pager
```

Не запускайте сервис на рабочей ноде до принятия решения о включении. Установка сама не запускает его. Чтобы остановить guard:

```bash
sudo systemctl disable --now decimal-guardian.service
```

Остановка процесса не меняет состояние валидатора в сети. Если guard уже поставил валидатора на паузу, вручную выясните причину и отдельно активируйте его штатным инструментом.

## Обновление и восстановление

Повторно запустите установщик после изучения release notes. Он обновляет пакет и unit-файл, сохраняя конфиг, ключ и журнал транзакций. Если исход транзакции неизвестен, проверьте hash в `/var/lib/decimal-guardian/evm-tx.json` через EVM RPC или эксплорер. Пока результат не установлен, guard не выбирает новый nonce и не отправляет вторую транзакцию.
